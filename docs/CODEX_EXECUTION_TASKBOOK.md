## 2. 用户、痛点与目标

- 用户：校长、教学负责人、HR、IT/数据负责人、教师代表
- 痛点：教师和员工已在使用AI备课、批改、营销和客服，但机构缺少允许范围、核验责任、数据和工具边界。
- 目标：结合业务场景与平台规则制定AI使用政策、审批流程、人工核验、数据分级和违规处理。

## 4. 工作流

1. 盘点AI场景
2. 分级风险
3. 制定用途与数据规则
4. 设计人工核验和审批
5. 培训与例外管理
6. 试点和复核

## 5. 阶段状态

| 阶段 | 动作 | 退出成果 |
|---|---|---|
| S1_SCOPE_CONFIRMATION | 确认目标、校区/岗位/课程范围、期限、交付格式和可用资料。 | 任务确认单与最多3个关键缺口 |
| S2_EVIDENCE_INVENTORY | 盘点机构业务与角色、现有AI工具、典型场景、数据类别、地区要求、教学原则、可接受风险、审批角色，标记来源、版本、敏感字段与冲突。 | 证据清单、缺口表和冲突表 |
| S3_PROFESSIONAL_DIAGNOSIS | 围绕结合业务场景与平台规则制定AI使用政策、审批流程、人工核验、数据分级和违规处理。进行专业诊断，形成问题树和优先级。 | 问题树、风险和优先级 |
| S4_SOLUTION_DESIGN | 按盘点AI场景 → 分级风险 → 制定用途与数据规则 → 设计人工核验和审批 → 培训与例外管理 → 试点和复核设计首选方案和受限备选方案。 | 方案、责任人、完成标准 |
| S5_HUMAN_CONFIRMATION | 由负责人/教学/IT/法务复核AI允许场景、数据输入、人工核验、处罚和例外审批。 | 确认记录、未决项和升级项 |
| S6_FINAL_DELIVERY | 生成完整交付成果，执行结构、证据、安全、品牌和独立安装检查。 | 最终成果、范围限制和复盘指标 |

## 6. 核心成果

- `场景红黄绿表`
- `审批流程`

## 7. 差异化与排重

- 与现有产品：隐私影响评估看单个数据场景；本产品建立组织级AI使用治理和持续审批制度。
- 排重检查：有限重叠；共享治理和合规概念，但本产品专用于AI工具使用与内容核验。
- 独立理由：只安装本 Agent 即可制定机构级AI政策，不依赖任何外部模型。

## 8. 安全与人工门禁

- 复核角色：负责人/教学/IT/法务
- 复核范围：AI允许场景、数据输入、人工核验、处罚和例外审批
- 不调用外部收费API。
- 不自动修改外部系统、执行退款、审批合同、处分员工或联系外部人员。
- 高风险产品完成状态必须确认人工复核。
